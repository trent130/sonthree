# Runbook: starting the lanes

## 0. Pre-flight on `main` (15 minutes, once)

Read `agents/SCHEDULE.md` first: the dates in `docs/BUILD_PLAN.md` are out of date and the cut order is already in force.

1. **`contracts/AGENTS.md` should not exist.** The contracts folder holds only contract files. If it is a duplicate of the root `AGENTS.md`, delete it and regenerate `contracts.lock` with `scripts/contracts_lock.py` (check its `--help`). Then `make contracts-lock-check` must pass. This is the only time the lock is regenerated by hand.
2. **Untrack build output.** `out/`, `*.egg-info/` and `__pycache__/` do not belong in git. `lanes.py scaffold` adds them to `.gitignore`; also run `git rm -r --cached out receipts_foundation.egg-info services/common/src/receipts_foundation.egg-info` for anything already tracked.
3. **Tests exist?** Your tree listing shows no test files under `services/common` or `services/generator`. If the listing was filtered, ignore this. If not, ask the foundation agent for its conformance suite and the generator's determinism, validity and realism tests before merging: every lane's reviewer will lean on them.
4. **Finish and merge the generator** (`make accept-generator`). Lanes can start before it merges, because they stub from `contracts/examples`, but merge it first.
5. `python scripts/lanes.py scaffold`, add `-include make/*.mk` to the root `Makefile`, delete its placeholder `accept-<lane>` targets (for stats, verifier, agents, overlay, evals, web, azure), commit.

## 1. Create worktrees and prompts

```
python scripts/lanes.py create --setup      # one worktree and one virtualenv per lane
python scripts/lanes.py prompts             # add --no-subagents if your agent has no subagent tool
python scripts/lanes.py list
```
Each worktree gets its **own** virtualenv. A shared editable install would point every lane at one checkout and hide cross-lane breakage.

## 2. Launch order (limit concurrent agents to what your rate limits allow)

| Start | Lanes | Why |
|---|---|---|
| now | verifier (03), stats (02), overlay (05), web+api (08) | critical path and the biggest unknowns |
| next | agents (04), evals (06) | need stubs only; start as soon as a slot frees up |
| in parallel, human-gated | azure (07) | task 1 needs you to confirm subscription, region and model quota |
| last | integration (09) | after wave 1 merges; create its worktree with `--force` |

Open each worktree folder in its own VS Code window or agent tab, paste `agents/launch/<lane>.md`, and let it run.

## 3. While they run

- `python scripts/lanes.py list` is your dashboard (agent state, ahead/behind, dirty).
- Read `.agent/QUESTIONS.md` in each worktree. `CONTRACT:` entries need you; `CROSS-LANE:` entries need a change on `main`.
- Run the reviewer in a **different model** from the implementer when you can. Same-model review shares blind spots.
- A lane showing `blocked` has hit the 3-round cap on a task. Read the last review file and decide: fix the requirement, accept the finding, or cut.

## 4. Merging (you, one lane at a time)

```
python scripts/lanes.py sync <lane>
python scripts/lanes.py gate <lane>        # contracts, foundation and the lane's own accept target
git merge --no-ff lane/<spec> -m "lane(<name>): <summary>"
python scripts/lanes.py sync               # everyone else rebases
```
Merge order: generator, stats, verifier, overlay, evals, agents, web, azure, integration.

## 5. Things only you can do

Confirm Azure access and model quota (spec 07 task 1). Review the Swahili text (set `human_reviewed` only through the review tool). Decide `CONTRACT:` questions. Record and upload the video. Create the project page and submit.

## Known failure modes

| Symptom | Likely cause | Response |
|---|---|---|
| a lane keeps re-opening a finished task | reviewer inventing minor issues | the protocol only loops on blocker and major with evidence; reject findings without it |
| tests go green but behavior is wrong | tests weakened or hard-coded fixtures | lane review's mutation check; diff test files for deletions and `xfail` |
| rebase conflicts in `Makefile` or `pyproject.toml` | someone edited a shared file | revert; lanes edit only their own `make/lane-*.mk` and service `pyproject.toml` |
| lane import works only on your machine | shared editable install | recreate the lane venv with `create --setup` |
| everything slows down | too many agents at once | pause the lowest-priority lane, resume later |
