# Design: Verifier

## Pipeline
```
claim ─▶ dependencies verified? ─▶ DETERMINISTIC CHECKS ─┬─ any fail ─▶ verdict(rejected, codes, hint)
                                                         └─ all pass ─▶ JUDGE (if needed) ─▶ verdict(verified | rejected)
                                         judge unavailable ─▶ no verdict, claim stays pending, retry
```
Checks run in a fixed order and all deterministic checks run even after the first failure, so the verdict lists every failed check. The judge runs only when every deterministic check passed.

## Deterministic semantics

**evidence_supports_assertion**, by assertion kind:
- `event_occurred`: some cited event (an `event` ref or inside a `seq_range`) has `type == event_type`, `match_time_ms` inside the window, belongs to the subject (player: `player_id`; team: `team_id`), and equals every entry in `attributes` against its payload.
- `metric_value` / `metric_comparison` / `metric_trend`: at least one cited event or snapshot involves each subject and lies in the window; a `metric_snapshot` ref must match subject, metric and window.
- `causal_explanation`: not applicable (skipped); covered by 2.5 and 2.6.

**Attribution when event_occurred fails** (first rule that matches the best candidate, the cited event closest in type and time):
1. no cited event has the right `type` → `evidence_irrelevant`
2. right type and window, wrong player → `wrong_player`; wrong team → `wrong_team`
3. right type and subject but outside the window → `wrong_time_window`
4. right type, subject and window but an `attributes` entry differs → `wrong_value`
5. evidence is only `role: context` events and none is primary → `missing_evidence`
A later rule never overrides an earlier match. The eval harness scores only the primary code, so a second code is allowed.

**assertion_numeric_match:** `stats_ref.StatsContext(events, as_of_seq).metric(...)` for each subject, then compare with the assertion's `op`, `value`, `tolerance`. A comparison fails with `wrong_comparison`, a trend with `wrong_trend_direction`, a value with `wrong_value`. If `stats_ref` returns undefined the claim is rejected with `wrong_value` and the hint says "undefined in this window".

**Causal patterns (pattern-first causality).** A registry of small predicates over the events between the cause and effect windows, each tied to a `possession_id` chain. Initial patterns:
1. *Forced turnover:* a `pressure` with `forced_turnover` true, followed within 5 s by a `tackle` won or a `possession_change` to the pressing team, by the same pressing team, within 10 m.
2. *Turnover to chance:* a `possession_change` (cause `tackle` or `interception`) followed by a `shot` by the gaining team **in the possession spell that change started** within 20 s.
3. *Pass to shot:* a `shot` whose `assist_event_id` is a pass in the same spell, within 8 s.
A causal claim is accepted only if its cause and effect claims map onto the endpoints of a registered pattern. Everything else is `unsupported_causal`. The judge never approves causality. This makes the hardest label class deterministic and the Analyst's causal output safe by construction. Add patterns only with a test.

**rendering_entails_assertion, numeric pre-pass:** extract numerals and shirt-number references (`No. 5`) from the rendering. Each must map to the assertion, an evidence event (player shirt number from the roster) or a recomputed value. Extra numerals fail with `rendering_adds_detail`, contradicting numerals with `rendering_contradicts`.

## Judge
`services/verifier/judge.py`, through the cassette LLM client. Inputs: assertion JSON, the minimal verified facts (resolved events, recomputed values, roster names), the rendering and its language. Output schema: `{entails: bool, adds_unsupported_detail: bool, contradicts: bool, reason: string}`. A rejection maps to `rendering_adds_detail` or `rendering_contradicts`. For translations the judge also gets the English rendering and returns `{faithful: bool, reason}`; failure maps to `translation_drift`.

## Rewrite hints
Generated by templates from the failed check, never by the model: "evidence ev_0000006 shows p_205, the claim says p_206", "window 2000-3000 ms excludes evidence at 6100 ms", "recomputed xg is 0.31, claim says 0.46", "rendering mentions 'best of the half', which no evidence supports".

## Ids, lineage and idempotence
`verdict_id` allocated per match. `attempt` = 1 + the number of verdicts already recorded for the claim's `supersedes` lineage. A claim already holding a verdict returns it.

## Service
`verifier.runner` subscribes to `claims`, publishes `verdicts`. CLI: `python -m verifier check --events E --claims C --out V` and `python -m verifier eval --manifest M` (delegates to spec 06).

## Testing
Unit tests per check against hand-built claims; the 14-label example eval set as a smoke test; deterministic-class operators at 100 percent on the full set; judge tests in replay mode with a cassette per label; property test: a verified verdict never accompanies a claim that `validate.check_claims` rejects.
